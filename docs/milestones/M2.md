# Milestone M2 — Organize + Save (v0.2)

**Goal:** faithful structural editing: reorder, rotate, delete, insert, import, merge, split and extract pages, saved incrementally by default, with the save impact always visible and crash-safe undo. This milestone introduces the `doc` and `ops` crates ([ADR-0009](../adr/0009-non-destructive-document-model.md), [data-model.md](../architecture/data-model.md)). Plan reference: [`PLAN.md` §G, §K](../PLAN.md) (phase 2). Estimated effort: 8–10 weeks.

**How to use this file:** the *one task per session* protocol in [`CLAUDE.md`](../../CLAUDE.md) and the [milestone rules](README.md#rules-for-every-milestone).

**Standard checks** (implied by every task): `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace && cargo deny check`, plus for `app/`: the CMake build, `clang-format --dry-run -Werror` and the Qt tests (`ctest`).

**Rules carried over from M1** (every task below assumes them):

- **Protocol:** every change to `Request`/`Response` in `crates/ipc` bumps `PROTOCOL_VERSION` (9 at the end of M1), keeps `Hello` frozen, appends new variants after the existing ones (postcard numbers variants by position), adds round-trip and validation tests in `crates/ipc` and a size cap on every variable-length field (a frame is at most `MAX_FRAME_BYTES`, 1 MiB). New client calls and events go into `crates/engine-client/src/client.rs` and the cxx bridge in `crates/engine-client/src/bridge.rs`; Qt sees them through `app/src/bridge/EngineSession.*`.
- **The engine writes no file and cannot be given a handle after it starts.** Handles are inherited at spawn only (`crates/engine/src/args.rs`; Windows AppContainer handle list, ADR-0017; Linux Landlock plus a seccomp deny list that has no way to receive a descriptor, ADR-0018). Anything the engine must give the UI (a saved revision) travels in `Response` messages, and anything the UI must give the engine travels in `Request` messages ([process-model.md](../architecture/process-model.md), lifecycle step 6).
- **Windows holds the open document with `FILE_SHARE_READ` only** (M1 task 2), and the engine maps it. The file cannot be renamed over, replaced or deleted until that engine has released it, so a save of the open file ends the engine (task 9a).
- **Untrusted input:** `doc`, `ops` and every other crate that touches PDF bytes follow invariant 5 (no panics, every walk bounded by `cos::limits`, new limits go into `Limits`/`LimitKind`, typed `thiserror` errors). `unsafe` stays forbidden in both new crates.
- **UI text and accessibility:** every string a person reads goes through `tr()` with an explicit context (`vellora::Name`) and `cmake --build <dir> --target update_translations` refreshes `app/translations/vellora_en.ts`; `tst_untranslated_literals` must stay green. Text that comes from a file (page labels, bookmark titles, field names, file names) is plain text, and tool tips made of it go through `plainToolTip` (`app/src/PlainText.h`). Every new action is a `Command` in `MainWindow::commands()` (a title, shortcuts, appears in the palette; `tst_commands` fails otherwise), `docs/user/shortcuts.md` is regenerated (`QT_QPA_PLATFORM=offscreen build/vellora --export-shortcuts docs/user/shortcuts.md`; CI diffs it), custom-painted parts use palette colours (high contrast), nothing animates (`tst_accessibility` fails on a `QAbstractAnimation`), and new widgets get accessible names. Add the user-visible change to `CHANGELOG.md` and the matching page of the manual in `docs/user/`.
- **Frame time:** UI changes keep the 8 ms budget of our code (`UiWatchdog`; `tst_canvas_render`, `tst_thumbnails_frame_time`). Those two are disabled on macOS CI (decision 8); a new frame-time test follows the same pattern and the same switch.
- **Dependencies:** a new external crate is justified in the commit body, passes `cargo deny check`, and `THIRD_PARTY_LICENSES` is regenerated (`cargo test -p xtask` fails when it is stale; procedure in `third_party/README.md`).
- **Packaging:** the MSI, Flatpak and dmg smoke tests (`.github/workflows/packaging.yml`, M1 task 23) run on pull requests that touch packaging. Files Vellora writes while running (temp files, the edit journal of task 10b) must not break the Windows "nothing left behind" check; user data made by use is kept on uninstall on purpose, as settings and logs are.
- **Tests are evidence:** corpus tests fail, not skip, without the corpus or `qpdf`; a loosened tolerance needs a `Deviation:` note.

## M2 acceptance criteria

- [ ] For every page operation × every corpus document it applies to, the invariant harness proves:
  - `qpdf --check` passes
  - an incremental save keeps the original bytes as an identical prefix
  - **untouched pages render pixel-identically**
  - page count and order are as expected
- [ ] Reordering and rotating in a 5,000-page document is instant in the UI. An incremental save finishes in < 2 s (performance target, enforced in nightly).
- [ ] Killing the engine or the app in the middle of an edit session loses no edits (journal replay, tested).
- [ ] Every save shows its `SaveImpact` before writing. Deleting pages and saving incrementally warns that deleted content stays recoverable and offers *Save Clean*.
- [ ] The CLI performs every page operation with `--json` output, and `--require-incremental` fails if the save would be a full rewrite.
- [ ] Inspector v2 shows the object tree, fonts, images and size attribution.
- [ ] Tagged pre-release `v0.2.0`, only if the maintainer asks.

### - [ ] Task 1: `doc` crate: session, transactions, history
- **Goal:** the non-destructive edit model of ADR-0009 as code.
- **Do:**
  - New crate `crates/doc` (`vellora-doc`; add it to the workspace `members` and `[workspace.dependencies]`; depends on `vellora-cos` and `thiserror` only):

  - Refuse to open a session on a document whose `ObjectStore::is_locked()` is true. A `ObjectStore::repaired()` store is allowed (it is saved in full, task 7b).
  - ADR "Document session API" (next free number after ADR-0019). `#![forbid(unsafe_code)]`; no panics on input (invariant 5); `lib.rs` header states responsibility and boundaries.
- **Acceptance:** unit tests for transaction commit/abort, undo/redo, nested resolution, and epoch bumps. A property test (`proptest`): applying then undoing any generated transaction gives back an object-identical document.

### - [ ] Task 8a: The edit session in the engine
- Part of task 8 (`ApplyOps`, `Undo`, `Redo` and the preview). Protocol bump; client and bridge calls included so the UI tasks can start.
- **Do:**

### - [ ] Task 8b: Planning and streaming a save
- Part of task 8 (`PlanSave`, `Save`, `SaveChunk`, `Saved`).
- **Do:**
  - Requests `PlanSave { mode }` → `SaveImpact` (task 7b's type, size-capped) and `Save { req_id, mode }` → any number of `SaveChunk { req_id, offset, bytes }` (at most 256 KiB each, in order) and one `Saved { bytes_written }`. An incremental save sends only the appended bytes (the UI side prepends the original, task 9a); a full rewrite sends the whole file. `Cancel` applies; a save on its own thread never delays a tile or a `Cancel`.
  - Backpressure and deadlines: the pipe blocks the writer thread when the UI is slow; the client times a save by progress (a chunk or a heartbeat within a configurable period), not by total time, so a 500 MB rewrite is not killed.
