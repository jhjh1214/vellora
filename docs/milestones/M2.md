# Milestone M2 — Organize + Save (v0.2)

**Goal:** faithful structural editing: reorder, rotate, delete, insert, import, merge, split and extract pages, saved incrementally by default, with the save impact always visible and crash-safe undo. This milestone introduces the `doc` and `ops` crates ([ADR-0009](../adr/0009-non-destructive-document-model.md), [data-model.md](../architecture/data-model.md)). Plan reference: [`PLAN.md` §G, §K](../PLAN.md) (phase 2). Estimated effort: 8–10 weeks.

**How to use this file:** the *one task per session* protocol in [`CLAUDE.md`](../../CLAUDE.md) and the [milestone rules](README.md#rules-for-every-milestone). Standard checks as in M1.

## M2 acceptance criteria

- [ ] For every page operation × every corpus document it applies to, the invariant harness proves:
  - `qpdf --check` passes
  - an incremental save keeps the original bytes as an identical prefix
  - **untouched pages render pixel-identically**
  - page count and order are as expected
- [ ] Reordering and rotating in a 5,000-page document is instant in the UI. An incremental save finishes in < 2 s (performance target, enforced in nightly).
- [ ] Killing the engine or the app in the middle of an edit session loses no edits (journal replay, tested).
- [ ] Every save shows its `SaveImpact` before writing. Deleting pages and saving incrementally warns that deleted content stays recoverable and offers *Save Clean*.
- [ ] The CLI performs every page operation with `--json` output, and `--require-incremental` fails if the save would be a full rewrite.
- [ ] Inspector v2 shows the object tree, fonts, images and size attribution.
- [ ] Tagged pre-release `v0.2.0`, only if the maintainer asks.

## Phase A: the document model

### - [ ] Task 1: `doc` crate: session, transactions, history
- **Goal:** the non-destructive edit model of ADR-0009 as code.
- **Do:**
  - New crate `crates/doc` (`vellora-doc`):
    - `Document` (thin session over `cos::ObjectStore`)
    - `Transaction` (object replacements, new objects, freed refs; new object numbers allocated past `/Size`)
    - `ChangeSet` (immutable result)
    - `History` (linear undo/redo of ChangeSets)
    - a change *epoch* for cache invalidation
  - Object resolution goes through the pending ChangeSets first, then `cos`.
  - Typed read views to start with: `Catalog`, `PageTree`, `Page` (with resolved inherited attributes: `/Resources`, `/MediaBox`, `/CropBox`, `/Rotate`).
  - ADR "Document session API". `#![forbid(unsafe_code)]`; no panics on input (invariant 5).
- **Acceptance:** unit tests for transaction commit/abort, undo/redo, nested resolution, and epoch bumps. A property test: applying then undoing any generated transaction gives back an object-identical document.
- **Depends:** 0

### - [ ] Task 2: Page-tree mutation primitives
- **Do:**
  - In `doc`:
    - remove, insert or move page refs
    - push inherited attributes down into a page dict before it moves to a different parent
    - rebuild the `/Pages` tree as a balanced tree (fan-out ≤ 64) of **new** intermediate nodes, while **page objects keep their object numbers** (identity for annotations `/P`, structure tree and signatures)
    - fix `/Parent` and `/Count`
  - A page-index cache invalidated by epoch.
- **Acceptance:** tests on flat, deep and inheriting trees (fixtures generated in tests). After every mutation, `cos` re-reads the saved result with the expected page order and attributes.
- **Depends:** 1

### - [ ] Task 3: `ops` crate: page operations
- **Do:**
  - New crate `crates/ops` (`vellora-ops`). `Operation` is a `serde` enum and the shared vocabulary of GUI commands, the CLI and future pipelines.
  - Page operations: `RotatePages{selection, degrees}`, `DeletePages`, `MovePages{selection, to}`, `DuplicatePages`, `InsertBlankPages{at, count, size}`, `CropPages{selection, box}` (sets `/CropBox`; warns "crop hides, doesn't remove").
  - `PageSelection` reuses the page-spec parser from M1 task 19 (move it into `ops`).
  - Each op is validated, then applied as one `Transaction`. Results report the pages changed and pages added or removed.
- **Acceptance:** unit tests per op, including edge cases (empty selection, out of range, delete all pages refused).
- **Depends:** 2

### - [ ] Task 4: Keep references consistent after deleting and moving pages
- **Do:** when pages are deleted:
  - outline items pointing at them keep their title, their destination becomes null, and they're greyed out in the UI
  - `/Dests` and the named-destination tree entries are removed
  - AcroForm `/Fields` lose widgets on deleted pages, and a field with no widgets left is removed
  - `/PageLabels` are rewritten so the remaining pages keep their labels
  - `/OpenAction` to a deleted page falls back to page 1
  - structure tree: elements referring to deleted pages are detached, and the document is flagged "tags may be incomplete"
- **Acceptance:** fixtures with outlines, named destinations, forms, labels and tags. After deletion, nothing references a freed object (a test walks the graph).
- **Depends:** 3

### - [ ] Task 5: Copy pages between documents
- **Do:**
  - Deep-copy a page's object graph from a source document into a target transaction, with renumbering. Excluded: `/Parent`; also `/StructParents`, which is dropped with a "tags not imported" flag.
  - Deduplicate identical streams (fonts, images) by content hash within one import.
  - Annotations: fix up `/P` and `/IRT`. Form fields: merge into the target `/AcroForm` (renaming on collision, `name#2`) and merge `/DR` resources. Optional content: merge `/OCProperties`. Named destinations are imported for internal links, and imported signature values are stripped (fields kept unsigned).
  - Ops: `ImportPages{source, selection, at}` and `Merge{sources}`.
- **Acceptance:** corpus test: import every page of 30 corpus documents into a blank document. Each imported page renders pixel-identically to its source page. qpdf check passes.
- **Depends:** 3

### - [ ] Task 6: Extract and split
- **Do:**
  - `ExtractPages{selection} → new document` and `Split{by: Ranges | EveryN | TopLevelBookmarks | MaxBytes}` produce new documents through task 5's copy plus the full writer.
  - The source document is unchanged.
  - Output names come from a template (`{name}-{index}`, `{name}-{bookmark}`), sanitised for the filesystem.
- **Acceptance:** corpus tests: extracted pages are pixel-identical to their originals. Splitting then merging gives the same page renders.
- **Depends:** 5

## Phase B: saving

### - [ ] Task 7: Save planner and streaming writers
- **Do:**
  - `SaveImpact{mode, reasons, signatures, recoverable_content, lossy_steps}` computed from the pending ChangeSets and the document's state: signatures present, repaired, encrypted.
  - Recoverable content is true when an incremental save would leave deleted pages, replaced streams or removed annotations readable in older revisions.
  - Make the `cos` full and incremental writers write to any `Write + Seek` sink instead of building a `Vec<u8>` (M0 task 12 follow-up), keeping a bounded buffer.
- **Acceptance:** planner unit tests for every reason. Writing the 500 MB synthetic document with a full rewrite keeps peak memory under 2× the largest single object, plus a fixed buffer (measured in the test).
- **Depends:** 1

### - [ ] Task 8: Engine edit session protocol
- **Do:**
  - Protocol: `ApplyOps{ops} → OpsApplied{changed pages, page count, epoch}`, `Undo`, `Redo`, `PlanSave{mode} → SaveImpact`, `Save{mode, output_handle_token} → Saved{bytes_written}`.
  - The UI creates the temp output file and passes **its handle** to the engine (the engine still opens no path). Allowed by the sandbox from M1 tasks 4–5: an inherited handle, writes only.
  - After `Saved`, or for preview after each apply, the engine re-opens the new revision in PDFium (ADR-0016) and invalidates only the affected pages' tiles.
  - Imports read a second document through a second handle passed by the UI.
- **Acceptance:** engine integration tests for each message, including undo after save and a crash during save (no partial output is ever renamed; task 9 does the rename).
- **Depends:** 3, 7

### - [ ] Task 9: Save, Save As, Save Clean in the UI
- **Do:**
  - Commands: Save (Ctrl+S, incremental by default), Save As, **Save Clean** (full rewrite and garbage collection: removes older revisions, signatures and recoverable content, shown in a confirmation).
  - Write protocol: temp file in the target directory → engine writes → fsync → self-check (a **fresh** engine opens the temp file; page count and the first page's render match) → atomic rename (`ReplaceFileW` / `rename`). On failure the original is untouched and the temp file is removed.
  - A **save-impact bar** above the canvas while there are unsaved changes, explaining the mode and warnings in one line, with *Details*.
  - Unsaved indicator in the tab title, a prompt on close, and read-only files force Save As.
- **Acceptance:** Qt tests for each save path, including a disk-full simulation (the write fails, the original is intact) and a self-check failure. The impact bar text is covered by snapshot tests.
- **Depends:** 8

### - [ ] Task 10: Crash-safe edit journal
- **Do:**
  - The engine client keeps the serialised `Operation` log of the session (ops are already `serde`). After an engine crash, it re-spawns, re-opens and **replays** the log before showing the document again.
  - The log is mirrored to an app-data journal file (fsync'd per op) keyed by document identity. On app start after a crash, offer *Recover unsaved changes* for each journal, *Discard* removes it. Journals are deleted after a successful save or close-without-saving.
  - Journals contain op parameters only, never document bytes. Imported source documents are referenced by path + size + mtime, and recovery reports missing sources.
- **Acceptance:** tests: kill the engine after 10 ops, then the state is identical; kill the app, restart, recover, and the saved result equals the uninterrupted session's result byte-for-byte.
- **Depends:** 8
