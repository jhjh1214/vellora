# Milestone M7 — Redaction, sanitisation, password protection (v0.7)

**Goal:** **real** redaction that removes content, not black boxes over it: mark → review → apply → **verify**. Also sanitisation that strips hidden and risky content, and password protection with modern encryption. Plan reference: [`PLAN.md` §H, §K](../PLAN.md) (phase 7), [security-model.md § Redaction leaks](../architecture/security-model.md), and the M0 note on writing new security setups. Estimated effort: 10–12 weeks.

**How to use this file:** the *one task per session* protocol in [`CLAUDE.md`](../../CLAUDE.md) and the [milestone rules](README.md#rules-for-every-milestone).

## M7 acceptance criteria

- [ ] **Leak suite:** for every channel (text, invisible/OCR text, Form XObjects, images incl. masks, vector paths, annotations, form values, links, outline, named destinations, metadata/XMP, structure tree Alt/ActualText, thumbnails, embedded files, earlier revisions, hidden layers), a secret placed in the redacted area is **absent from every decoded byte of the output**.
- [ ] Apply always produces a full rewrite with no earlier revisions and a new `/ID`. The post-apply verification report passes, and if verification fails, no output is written.
- [ ] Redaction marks are standard `/Redact` annotations, so marked-but-not-applied files open for review in Acrobat.
- [ ] Sanitisation profiles remove what they list (tested per item).
- [ ] Password protection with AES-256 (R6): set, change and remove passwords and permissions; files open in Acrobat and PDFium.
- [ ] An external review of the redaction design has been invited (issue or advisory), and its findings are triaged.
- [ ] Tagged pre-release `v0.7.0`, only if the maintainer asks.

## Phase A: marking and reviewing

### - [ ] Task 1: Redaction marks
- **Do:**
  - Marks are standard **`/Redact` annotations** (§12.5.6.23) with `/QuadPoints` or `/Rect`, `/IC` fill colour, `/OverlayText`, `/Repeat`.
  - Mark sources: area, text selection, whole page(s), and **search patterns** (literal or regex; presets for email, phone, payment card with Luhn check, IBAN, and configurable national IDs) across the document, with per-hit review.
  - Ops: `AddRedactionMarks`, `RemoveRedactionMarks`. Marks save incrementally like other annotations.
- **Acceptance:** tests for each source. Pattern presets are tested against positive and negative examples.
- **Depends:** 0

### - [ ] Task 2: Redact mode UI
- **Do:**
  - Redact mode: mark tools, a panel listing all marks (page, matched text, source pattern) with accept/remove, and an overlay preview (fill + overlay text).
  - **Apply** shows a summary:
    - what will be removed per channel
    - that it's irreversible
    - that the output is a new file (default `<name>-redacted.pdf`)
    - that signatures will be removed

    It requires an explicit confirmation.
- **Acceptance:** Qt tests drive mark → apply. The summary snapshot is tested.
- **Depends:** 1

## Phase B: removing content

### - [ ] Task 3: Text removal
- **Do:**
  - Remove every glyph whose box intersects a mark, using the M4 interpreter. This covers visible and invisible text (`Tr 3`, OCR layers), text inside Form XObjects (copy-on-write per page) and Type3 glyphs as whole glyphs.
  - Adjust `TJ` kerning so the remaining glyphs keep their positions.
  - Any text the interpreter can't place reliably inside a marked page region makes the whole affected text object removed, and reported.
- **Acceptance:** leak tests for each text form. Pixels outside the marks are unchanged.
- **Depends:** 2

### - [ ] Task 4: Image removal
- **Do:**
  - Decode intersecting images in the engine through PDFium's image access (all filters), including `/SMask` and `/Mask`. Overwrite pixels in the mark area with the fill colour and re-encode (Flate, lossless, by default; JPEG at matched quality as an option).
  - Images shared across pages are copied on write. Inline images too.
  - An image that can't be decoded is **removed entirely**, and that's reported.
- **Acceptance:** leak tests. Rendering outside the marks is unchanged within JPEG tolerance when that option is used.
- **Depends:** 3

### - [ ] Task 5: Vector and shading removal
- **Do:**
  - Paths and shadings fully inside a mark are removed. Paths that **partly intersect a mark are removed entirely** and listed in the report. Clipping is not removal, so we never rely on a clip to hide vector data.
  - Form XObjects are handled recursively (copy on write).
- **Acceptance:** leak tests with vector-drawn text (glyphs as paths).
- **Depends:** 3

### - [ ] Task 6: Non-content channels
- **Do:**
  - Inside marked areas:
    - remove annotations (or scrub their contents)
    - remove form fields and their values
    - remove link annotations and their targets
  - Document-wide, for strings matched by pattern marks or explicitly selected:
    - outline titles
    - named destinations
    - metadata (`/Info`, XMP)
    - structure tree `Alt`/`ActualText`/`E`
    - page thumbnails `/Thumb`
    - embedded file names and contents
    - document JavaScript
    - hidden optional-content in the area
    - `/PieceInfo`
- **Acceptance:** a leak test per channel.
- **Depends:** 3

### - [ ] Task 7: Apply pipeline and verification
- **Do:**
  - Apply runs: content removal (tasks 3–6) → overlay (fill + optional overlay text, drawn as page content) → **full rewrite** (GC, no earlier revisions, new `/ID`, unencrypted unless the user re-encrypts in the same step) → **verification**:
    - (a) PDFium text extraction inside every mark is empty
    - (b) our interpreter finds no glyphs inside marks
    - (c) a high-DPI render of each mark area is the fill colour
    - (d) every decoded stream, string and name in the output is scanned for the redacted strings
  - Verification failure means no output, and a report explains what leaked.
  - A redaction report (JSON + human-readable) is optionally saved next to the output.
- **Acceptance:** the full leak suite passes. A deliberately broken remover (test flag) makes verification fail and no file is written.
- **Depends:** 4, 5, 6

### - [ ] Task 8: Sanitisation
- **Do:**
  - `Sanitize{profile}` with a full rewrite. Profile items:
    - metadata (Info/XMP)
    - document and field JavaScript
    - embedded files
    - Launch / URI / SubmitForm / ImportData / GoToR actions
    - annotations
    - form data
    - hidden layers
    - unreferenced objects
    - private application data (`/PieceInfo`)
    - thumbnails
    - alternate images
    - search indexes
  - A "Remove hidden information" preset; custom checklists. Report of what was found and removed.
- **Acceptance:** a test per item (present before, absent after, document still renders).
- **Depends:** 0

### - [ ] Task 9: Password protection
- **Do:**
  - Writer support for a **new** Standard Security Handler setup: AES-256 R6 only for new encryption (older revisions are read-only support), random salts and file key via `getrandom`, permissions, and `/EncryptMetadata`.
  - Ops: `Encrypt{user_pw?, owner_pw, permissions}`, `ChangePasswords`, `Decrypt` (requires the owner password, or the user password when no owner password is set). Always a full rewrite.
  - UI dialog with a strength hint; passwords are zeroised. CLI `vellora encrypt|decrypt`.
  - ADR "Encryption on write".
- **Acceptance:** our encrypted output opens in PDFium, qpdf and pdf.js with the right passwords and permissions. Known-answer tests for key derivation.
- **Depends:** 0

## Phase C: CLI and assurance

### - [ ] Task 10: CLI `redact` and `sanitize`
- **Do:** `vellora redact <file> -o out.pdf [--pattern REGEX…] [--preset email,phone,…] [--region page:x,y,w,h…] [--marks marks.json] [--apply-existing-marks] [--report report.json]` and `vellora sanitize <file> -o out.pdf --profile hidden-info | --remove js,files,…`.
