# Milestone M4 — Object editing, tiers 1–2 (v0.4)

**Goal:** prove **content-stream surgery**: select page objects, then add text and images, move, resize or delete images, paths and text runs, while every byte we didn't touch stays identical. Also the page-stamping features Acrobat Pro users rely on: watermark, header/footer, page numbers, Bates numbering. This milestone creates the `content` crate ([data-model.md § Content edits, § Direct text editing tiers](../architecture/data-model.md)). Plan reference: [`PLAN.md` §G2, §K](../PLAN.md) (phase 4). Estimated effort: 10–12 weeks.

**How to use this file:** the *one task per session* protocol in [`CLAUDE.md`](../../CLAUDE.md) and the [milestone rules](README.md#rules-for-every-milestone).

## M4 acceptance criteria

- [ ] The content tokeniser is lossless: concatenating the token spans reproduces every corpus content stream byte-for-byte.
- [ ] Interpreter text-run boxes agree with PDFium's character boxes (median IoU ≥ 0.9 over the corpus text pages). Page objects carry provenance.
- [ ] Every edit changes pixels **only inside the union of the edited objects' old and new bounding boxes** (invariant harness over the corpus). Operators outside the edited ranges stay byte-identical.
- [ ] Add text (any script supported by the font subsystem) and add images (JPEG, PNG with alpha, others converted) work and extract/render correctly.
- [ ] Watermark, header/footer, page numbers and Bates numbering work from the UI and the CLI.
- [ ] Edits to objects we can't edit safely (inside patterns, Type3 glyph procedures, shadings) are refused with a clear reason, never approximated.
- [ ] Tagged pre-release `v0.4.0`, only if the maintainer asks.

## Phase A: understanding page content

### - [ ] Task 1: `content` crate: lossless tokeniser
- **Do:**
  - New crate `crates/content` (`vellora-content`, `forbid(unsafe_code)`).
  - Tokenise content streams into operands and operators with **byte spans**, built on `cos`'s lexer where possible.
  - Inline images (`BI … ID … EI`): find the end robustly (use `/L` or `/Length` when present; otherwise validate the candidate `EI` by checking that what follows parses as operators).
  - Bounded operand stack; malformed operators are kept as raw spans, never dropped.
- **Acceptance:** corpus test: token spans re-concatenate to the exact original bytes for every content stream. Fuzz target `content_tokenize` added.
- **Depends:** 0

### - [ ] Task 2: Graphics-state interpreter and page objects
- **Do:**
  - Interpret:
    - `q`/`Q` (bounded stack), `cm`, clipping (`W`/`W*` + the next painting op), path construction and painting
    - colour operators (recorded, not converted), `gs`
    - text objects (`BT`/`ET`, `Tc Tw Tz TL Tf Tr Ts Td TD Tm T* Tj TJ ' "`)
    - marked content (`BMC`/`BDC`/`EMC` with MCIDs)
    - `Do` for images and **Form XObjects** (recursion with depth limit and cycle detection), `sh`, inline images
  - Produce `PageObject = TextRun | Image | Path | Shading | FormXObject`, each with a device-space bounding box, its graphics state snapshot and **provenance**: `(stream ref, operator range, nesting path through Form XObjects)`.
- **Acceptance:** unit tests per operator group. Corpus test with no panics and bounded time (≤ 1 s per page at the 99th percentile).
- **Depends:** 1

### - [ ] Task 3: Glyph geometry and text decoding
- **Do:**
  - Decode text strings to character codes and Unicode:
    - simple fonts (`/Encoding` + `/Differences`, built-in encodings)
    - Type0 with `Identity-H`/`V` and embedded CMaps (parse `begincodespacerange`/`cidrange`/`bfchar`)
    - `ToUnicode`
  - Widths: `/Widths`, `/FirstChar`, the standard 14 metrics (from the `fonts` crate), Type0 `/W` `/DW`, basic vertical `/W2`, and Type3 `/FontMatrix`.
  - Per-glyph boxes from font ascent/descent/bbox.
  - Cross-check against PDFium's text boxes and record disagreements per document (a diagnostic, not a failure).
- **Acceptance:** median IoU ≥ 0.9 against PDFium on the corpus text pages, with the report attached to the PR. Unit tests for each encoding path.
- **Depends:** 2

### - [ ] Task 4: Content patches and resource handling
- **Do:**
  - `ContentPatch{stream, op_range, replacement}` applied by **splicing bytes**.
  - Appended streams: wrap the page's existing content as `q` (a new tiny first stream) … `Q` (a new tiny stream), followed by our new stream, so unbalanced original state can't leak into added content.
  - Copy-on-write for content streams and `/Resources` dicts **shared between pages** (patching one page must never change another).
  - Allocate collision-free resource names.
- **Acceptance:** tests: a shared-stream fixture, an edit on page 1 leaves page 2 pixel-identical; a page with unbalanced `q` renders added content correctly.
- **Depends:** 2

### - [ ] Task 5: Page objects over the protocol
- **Do:**
  - `GetPageObjects(page)` (bounded, paged) returns kind, bbox, stable id (provenance hash + epoch) and a properties summary: text (font name, size, colour, string excerpt) or image (pixel size, effective DPI, colour space, filter).
  - A `HitTest(page, point)` helper.
  - Cache per page with epoch invalidation.
- **Acceptance:** protocol tests. Latency: page objects for a heavy vector page (≥ 20,000 paths) arrive in < 500 ms.
- **Depends:** 3

## Phase B: editing

### - [ ] Task 6: Edit mode: selecting objects
- **Do:**
  - Edit mode: hover outlines by kind, click to select, Shift/Ctrl multi-select, rubber band, Tab through objects on the page.
  - Bounding-box handles (move, resize with Shift for aspect ratio, rotate).
  - Properties panel per kind. Objects that can't be edited are shown with a lock icon and the reason.
- **Acceptance:** Qt tests for selection logic. Frame-time test on a heavy vector page.
- **Depends:** 5

### - [ ] Task 7: Move, resize, rotate, delete
- **Do:**
  - Ops `TransformObjects{ids, matrix}` and `DeleteObjects{ids}`.
  - Images, Form XObjects, shadings and paths: wrap the operator range in `q <matrix> cm … Q`.
  - Text runs: split the enclosing `BT … ET` at the run boundaries and re-issue the text state and matrix, so only the run moves.
  - Partial deletion inside a `TJ` array removes those glyphs and inserts the kerning adjustment that keeps the remaining glyphs in place.
  - Refuse objects inside patterns, Type3 procs or with clip dependencies that would change other objects. Show a typed reason.
- **Acceptance:** per-op tests. Corpus invariant: pixels change only inside the old+new bbox union, and operators outside the edited ranges are byte-identical.
- **Depends:** 4, 6

### - [ ] Task 8: Add text
- **Do:**
  - A text-box tool in Edit mode: font picker (fonts subsystem), size, colour, alignment, line spacing and wrapping within the box. Text is shaped by `harfrust` and embedded as a subset.
  - Writes an appended content stream. Within the session the box stays re-editable (identified by marked content `/Span <</Vellora:TextBox …>>`). After reopening, it's ordinary page content until M6.
- **Acceptance:** tests: Latin, Arabic (RTL) and CJK strings render and extract back to the same Unicode (PDFium text). Golden renders.
- **Depends:** 7

### - [ ] Task 9: Add, replace and crop images
- **Do:**
  - `AddImage{page, rect, source}`:
    - JPEG passes through as `DCTDecode` (header validated, CMYK/Adobe-inverted handled)
    - PNG becomes Flate + predictor, with an `/SMask` for alpha
    - other formats are decoded with the `image` crate and stored as Flate
    - 16-bit sources are reduced to 8-bit
    - an embedded ICC profile is kept as `/ICCBased`
  - `ReplaceImage{id, source}` keeps the placement. `CropImage{id, rect}` adds a clip path.
  - The decoder runs **in the engine** (sandboxed) with dimension and memory limits.
- **Acceptance:** tests per format, including alpha; a decompression-bomb PNG is refused with a typed error.
- **Depends:** 7

### - [ ] Task 10: Watermark, header/footer, page numbers, Bates numbering
- **Do:**
  - `ops` built on tasks 8–9:
    - `AddWatermark{text | image, opacity, rotation, position, pages, behind_content}`: behind content prepends a stream, otherwise appends
    - `AddHeaderFooter{left/centre/right templates with {page}, {pages}, {label}, {date}, {filename}, margins, font, pages}`
    - `BatesNumber{prefix, start, digits, suffix, position, across_files}`
  - Each stamp is wrapped in marked content `/Artifact` with Vellora properties, so `RemoveWatermark` / `UpdateHeaderFooter` can find and replace it later.
  - Dialogs with live preview on the current page.
- **Acceptance:** tests: stamps render where expected on rotated and cropped pages; remove/update finds them after save and reopen; Bates numbering across 3 files is continuous.
- **Depends:** 8, 9

### - [ ] Task 11: Image DPI and placement in the Inspector
- **Do:** with page objects available, the Inspector's images list shows **effective DPI** and the pages and placements of each image, and the size attribution links to objects on the canvas.
- **Acceptance:** DPI values match a hand-computed fixture.
- **Depends:** 5

## Phase C: CLI and quality

### - [ ] Task 12: CLI for content editing
- **Do:**
  - `vellora objects <file> --page N [--json]`
  - `vellora add-text <file> --page N --at x,y --text … [--font …]`
  - `vellora add-image <file> --page N --rect … --image …`
  - `vellora watermark <file> --text … | --image … [--opacity …]`, plus `--remove`
  - `vellora header-footer <file> …`
  - `vellora bates <files…> --prefix … --start …`
  - Documented with examples.
- **Acceptance:** CLI tests and snapshots.
- **Depends:** 10

### - [ ] Task 13: Invariants, fuzzing and performance for content editing
- **Do:**
  - Invariant harness: on every corpus page with objects, delete the first image and path, move the first text run, add a text box and an image. Check bbox-limited pixel change, byte identity outside the edits and qpdf.
  - Fuzz targets: `content_interpret`, `content_patch` (random patches on fuzzed streams never panic; output re-parses).
  - Benchmarks: interpreter pages/s, `GetPageObjects` latency, and edit-commit latency on heavy pages. Added to the nightly gate.
- **Acceptance:** nightly green. Numbers recorded in `performance-targets.md`.
- **Depends:** 12
