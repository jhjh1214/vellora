# Milestone M6 — Text editing, tiers 3–4, and the macOS release (v0.6)

**Goal:** edit existing text in place, honestly. Single-line runs are re-encoded with the document's own font whenever its glyphs allow, and paragraphs are re-laid out inside high-confidence blocks. Any font substitution is visible and flagged. Also make macOS a first-class release platform. Plan reference: [`PLAN.md` §G2, §K](../PLAN.md) (phase 6) and the macOS commitment "MVP+1". Data model: [data-model.md § Direct text editing tiers](../architecture/data-model.md). Estimated effort: 12–14 weeks.

**How to use this file:** the *one task per session* protocol in [`CLAUDE.md`](../../CLAUDE.md) and the [milestone rules](README.md#rules-for-every-milestone).

## M6 acceptance criteria

- [ ] On the per-producer text-editing test set, single-line edits whose glyphs exist in the embedded font are **pixel-faithful** outside the edited run. Every font substitution is flagged in the UI and in the op result.
- [ ] Block edits reflow only within detected high-confidence blocks. Pixels outside the block are unchanged. Overflow is refused, never silently clipped.
- [ ] Find & replace reports, per occurrence, whether it can be edited in place, needs substitution or can't be edited, before applying.
- [ ] macOS: the engine is sandboxed with an enforced memory cap, all M1–M6 features pass their tests, and a **signed and notarised** universal `.dmg` is produced (decision #2).
- [ ] Tagged pre-release `v0.6.0`, only if the maintainer asks.

## Phase A: macOS as a release platform

### - [ ] Task 1: macOS engine sandbox and memory cap
- **Do:**
  - Apply a sandbox (Seatbelt) profile to the engine at spawn: no network, read-only access to system font and library paths, no file access otherwise, no `exec`. Only inherited handles are used.
  - Memory cap: macOS ignores `RLIMIT_AS`/`RLIMIT_DATA`, so the client polls the engine's footprint (`proc_pid_rusage`) and kills it above the limit, with the same typed error as other platforms.
  - ADR "Engine sandbox on macOS". Update the tracker.
- **Acceptance:** negative tests (no file, no socket, no exec) pass on macOS CI. A memory-bomb fixture is stopped within 1 s of crossing the cap.
- **Depends:** 0

### - [ ] Task 2: macOS platform conventions
- **Do:**
  - Application menu (About, Settings Cmd+, and Quit in the app menu), standard Cmd shortcuts.
  - Trackpad pinch zoom and smart zoom; Dark Mode; Retina tiles at device pixel ratio.
  - `Info.plist` document types (opt-in default viewer), Open Recent through the system, and the window tabbing behaviour decided consistently with our own tabs.
  - A **universal binary** (arm64 + x86_64) including the engine and PDFium per architecture.
- **Acceptance:** a manual checklist with screenshots. CI builds the universal app.
- **Depends:** 1

### - [ ] Task 3: Signed and notarised macOS release
- **Do:**
  - Codesign with hardened runtime (entitlements minimal; the engine gets its own stricter entitlements), notarise and staple in CI using repository secrets (maintainer-provided).
  - A `.dmg` with a drag-to-Applications layout.
  - A Homebrew cask draft in `packaging/`.
- **Acceptance:** a clean macOS VM opens the downloaded `.dmg` without Gatekeeper warnings, and the smoke test passes.
- **Depends:** 2

## Phase B: editing existing text

### - [ ] Task 4: Font-program analysis for editing
- **Do:**
  - For each font used on a page, determine its glyph coverage:
    - TrueType `cmap` and `glyf` presence
    - CFF charset
    - Type1 encoding (embedded Type1 via a permissively licensed parser, or convert to CFF with care)
  - Build reverse maps Unicode → code using `ToUnicode` + the font's own cmap.
  - Classify a text run against a proposed new string: **in place**, **needs font extension** (the full font is installed and its `fsType` allows embedding), **needs substitution**, or **not editable** (Type3, text as paths, unmappable encoding).
- **Acceptance:** classification unit tests per font technology. A per-producer report on the test set (task 11) attached to the PR.
- **Depends:** 0

### - [ ] Task 5: Line and run model for editing
- **Do:** from the M4 interpreter, group text runs into **lines**: baseline, direction, font, size, colour, `Tc`/`Tw`/`Tz`, glyph positions and gaps. Detect justified lines (variable word spacing). Keep provenance to every `TJ` element.
- **Acceptance:** line detection tests on single-column, multi-column, rotated and RTL fixtures.
- **Depends:** 4

### - [ ] Task 6: Tier 3: edit a run in place
- **Do:**
  - Op `EditTextRun{id, new_text, keep_following: Positions | Reflow}`.
  - Re-encode with the run's own font when classified *in place*. Otherwise either:
    - (a) embed a subset of the matching installed font as an **additional** resource and switch `Tf` for the edited span only, or
    - (b) substitute a metrically similar fallback (serif/sans/mono class, width-scaled to keep the line width) and **flag it in the op result**.
  - Following glyphs on the line either keep their positions (gaps absorbed by kerning) or shift.
  - `ToUnicode` stays correct for searching and copying.
- **Acceptance:** per-producer tests. The edited line extracts as the new text, and pixels outside the edited line's bbox are unchanged. Every substitution is reported.
- **Depends:** 5

### - [ ] Task 7: Inline text editing UI
- **Do:**
  - In Edit mode, double-click text to get a caret on the canvas. Typing shows a **UI-side preview** of the line (shaped with the font that will be used) and commits on Enter, focus loss or 1 s idle (ADR-0016 latency).
  - IME support for CJK and complex scripts (`QInputMethod`). Arrow and selection keys within the run/block, Esc to cancel.
  - A badge on edited runs whose font changed, with an explanation popover.
  - Undo per editing session.
- **Acceptance:** Qt tests for editing commands and IME composition (simulated). Frame-time test while typing.
- **Depends:** 6

### - [ ] Task 8: Block detection
- **Do:**
  - Layout analysis: lines → paragraphs (alignment, leading, indentation, spacing), columns and reading order.
  - Each block gets a **confidence** score from consistent font, size, leading and alignment and no overlapping non-text objects.
  - A debug overlay in Edit mode to visualise blocks.
- **Acceptance:** precision/recall of paragraph detection on a hand-labelled set of 50 pages ≥ 90%.
- **Depends:** 5

### - [ ] Task 9: Tier 4: reflow within a block
- **Do:**
  - Op `EditTextBlock{id, new_text}` re-lays out the text inside the block's bounds with the same font, size, leading and alignment (justification by word spacing; no hyphenation).
  - It replaces exactly the block's operator ranges. Font handling as in task 6.
  - If the text overflows the block: refuse with a reason, or with explicit user consent extend downward only when the space below is empty (checked against page objects).
  - Only for blocks above the confidence threshold. Otherwise offer Tier 3 per line.
- **Acceptance:** tests on the per-producer set: pixels outside the block are unchanged, and the text extracts correctly.
- **Depends:** 7, 8

### - [ ] Task 10: Find and replace text
- **Do:** Edit → Find and Replace (whole word, case, regex). A **dry-run report** shows each occurrence classified (in place / substitution / not editable), and the user applies all, selected or none. CLI `vellora replace-text <file> --find … --replace … [--regex] [--dry-run] [-o out]`.
- **Acceptance:** tests on fixtures. The dry-run classification matches the applied result.
- **Depends:** 9

### - [ ] Task 11: Per-producer test set and invariants
- **Do:**
  - Assemble a text-editing test set (licensed) from Word, LibreOffice, LaTeX (Type1/CFF subsets), InDesign, Chrome "Save as PDF", Google Docs and a scanner with OCR layer.
  - Scripted edits per document. Metrics: in-place rate, substitution rate, refusal rate, pixel-faithfulness.
  - Invariant harness: bbox-limited pixel change and byte identity outside the edited ranges. Fuzz target for edit ops.
- **Acceptance:** metrics report attached. Nightly includes the set.
- **Depends:** 10
