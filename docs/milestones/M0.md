# Milestone M0 — Walking skeleton

**Goal:** prove the process architecture, the license-clean dependency stack and the `cos` writer invariants end to end, with production OSS infrastructure in place. Plan reference: [`PLAN.md` §O](../PLAN.md). Estimated effort: 8–10 weeks for one developer.

**How to use this file:** follow the *one task per session* protocol in [`CLAUDE.md`](../../CLAUDE.md).
- Take the first unchecked task whose dependencies are checked.
- Implement only its scope and pass its acceptance checks plus the standard checks.
- Tick it, and add `Note:` lines for the next session.
- If a task proves much larger than described, split it here (e.g. 7a, 7b) before implementing.

This file is the hand-off between sessions. Notes go directly under the task they belong to.

**Standard checks** (implied by every task):
`cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace && cargo deny check`

## M0 acceptance criteria (from the plan)

- [ ] CI is green on Windows, Linux and macOS.
- [ ] `cargo deny check` passes; the third-party license list is complete.
- [ ] The engine opens ≥ 95% of corpus v0 without crashing. On the malformed/malicious subset, the **UI process never crashes**.
- [ ] Every incremental write in tests keeps the original byte prefix identical and passes `qpdf --check`.
- [ ] The 10,000-page synthetic document shows its first page in < 1.5 s on the dev machine. Scrolling never blocks the UI thread (UI watchdog log is clean).
- [ ] Re-open-after-commit latency is measured on the 10k-page and 500 MB documents and recorded in an ADR.

### - [x] Task 4: Lexer (ISO 32000-2 §7.2)
- **Do:**
  - Tokens with **byte spans**: numbers, literal strings (escapes, balanced parens, line continuation), hex strings, names (`#xx` escapes), delimiters, keywords, comments, `stream` keyword handling (EOL rules).
  - Whitespace and comments are tracked but skippable.
- **Acceptance:** tests for every token type plus malformed variants (unterminated strings, odd hex digits, huge numbers). A proptest shows the lexer never panics on arbitrary bytes.
- **Depends:** 3
- Note: API: `Lexer::new(data, &limits)`, `next_token()` (skips white space and comments), `next_raw()` (returns them too; spans tile the input), `seek`/`position`, and `skip_stream_eol()` for the bytes after the `stream` keyword. `Lexer<'a, 'l>` has separate lifetimes for data and limits so tokens can outlive the limits borrow.
- Note: `Token { kind, span: Range<usize> }`; offsets are positions in the slice given to the lexer (pass the whole file slice so spans are file offsets). Names and unescaped strings borrow (`Cow::Borrowed`); hex strings are always owned.
- Note: Tolerances (documented in `lexer.rs`): `--5` is -5; an integer over `i64` becomes `Real`, a real over `f64` clamps to `f64::MAX`; number-like junk (`1.2.3`, `12-34`, lone `-`) is a `Keyword`; non-hex chars in hex strings are ignored and an odd digit is padded; a bad `#` in a name stays literal; stray `)` / lone `>` is `TokenKind::Stray`.
- Note: Errors: unterminated `(`/`<` strings give `Error::Syntax { kind: UnterminatedString | UnterminatedHexString, offset }` with the position moved to the end of the data; limit errors (`max_name_bytes`, `max_string_bytes`) leave the position past the token so a recovery scan can continue. Parser (task 5) should treat `Stray` and `Keyword` junk as its own syntax errors.
- Note: `stream` EOL: `skip_stream_eol()` reports `StreamEol::{CrLf, Lf, Cr, Missing}`; only `CrLf`/`Lf` are spec-conforming, so task 5 should flag the others as recovered. Blanks before the marker are tolerated only if a marker follows.
- Note: Tests: unit tests per token type and malformed variant, plus proptests (never panics, always progresses, spans tile the input, hex/literal/integer round trips). Not yet run against the corpus; task 5/8 tests should do that.

### - [x] Task 5: Object parser
- **Do:**
  - Direct objects (null, bool, int, real, string, name, array, dict, ref `n g R`) and indirect objects `n g obj … endobj`.
  - Streams: `/Length` direct or indirect. If the length is wrong or missing, recover by searching for `endstream` within limits, and flag the recovery.
  - Every parsed object keeps its source span.
- **Acceptance:** tests including a wrong `/Length`, missing `endobj`, deep nesting hitting the limit, and dictionaries with duplicate keys (last one wins, documented).
- **Depends:** 4
- Note: API: `Parser::new/at(data, &limits)`, `parse_object()` (direct), `parse_indirect_object()` (returns `IndirectObject { id, object, span, recoveries }`), `seek/position`, and `.with_length_resolver(&|ObjRef| -> Option<i64>)` so the object store (task 9) can supply an indirect `/Length`. Model in `cos::object`: `Object { kind, span }`, `ObjectKind`, `Dict` (all entries kept, `get` = last wins), `Stream { dict, data: Range }` (raw bytes are never copied or decoded here).
- Note: `Recovery` flags every repair (`StreamLengthMissing/Unresolved/Wrong{declared}`, `StreamEolNonStandard`, `MissingEndobj`); the document layer should turn a non-empty list into the `repaired` reasons. A missing `endobj` leaves the next token unread so a sequential scan (task 8) can continue.
- Note: Streams: `/Length` is trusted only if `endstream` really follows; otherwise the first `endstream` within `max_decoded_stream_bytes` bounds the search (a literal `endstream` inside binary data can cut a stream short when `/Length` is wrong). No `endstream` at all is `SyntaxKind::MissingEndstream`.
- Note: Syntax errors in direct objects are not repaired here (stray `]`, non-name dict key, `/K` without value, unterminated array). Nesting recursion equals `max_nesting_depth` (default 64): do not raise it into the thousands without making the parser iterative.
- Note: Found while testing: the array loop must not swallow lexer errors when peeking (`peek_required`), otherwise an unterminated string reports as `UnexpectedEof`; the optional trailing tokens (`stream`, `endobj`) use the forgiving `peek`.
- Note: Throwaway smoke run over corpus v0 (not committed): scanning for `n g obj` headers found 7745 candidates in 275 files, 7680 parsed, 569 reported recoveries, 65 errors, no panics. The crude header finder produces false positives, so treat these numbers as a sanity check only; task 8 and 13 test real corpus behaviour.

### - [x] Task 8: Recovery scan
- **Do:**
  - When `startxref` or the xref is missing or broken, rebuild by scanning for `n g obj` headers and trailer dicts (or `/Root` candidates).
  - Set a `repaired` flag carrying the reasons.
  - Never trust offsets without validation.
- **Acceptance:** every corpus `malformed` file either opens (with `repaired = true`) or fails with a typed error. **No panics, no hangs** (a test timeout guards it).
- **Depends:** 7
- Note: API: `Xref::open(data, &limits)` / `open_with_budget` is the entry point the document layer should use: it reads the xref normally, and rebuilds if that fails (syntax or decode errors) or if `/Root` does not lead to a real object (`root_is_valid`). `Xref::repaired: Vec<RepairReason>` is the **`repaired` flag with reasons** (empty = not repaired): `XrefUnreadable(SyntaxKind)`, `XrefUndecodable`, `RootEntryInvalid`, `ObjectOffsetInvalid{number}`, `TrailerSynthesized`, `ObjectStreamNotExpanded{stream}`. `cos::recovery::rebuild(data, &limits, &mut budget, &reasons)` can be called directly (e.g. by the object store with `ObjectOffsetInvalid`). `Xref::lookup(num)` gives one entry without building `merged()`.
- Note: A rebuilt `Xref` has one revision of `SectionKind::Rebuilt` covering the whole file (so there is no revision history: saves should be full rewrites, per the data model). Offsets stay relative to the `%PDF-` header (`Xref::base`). **Task 9 must call `recovery::object_header_at(data, base, offset, number)` before trusting any in-use offset** and rebuild with `ObjectOffsetInvalid` when it fails: `open` only validates `/Root`.
- Note: Scan rules: sequential `n g obj` headers and `trailer` dictionaries; the scan resumes after each parsed object (so fake headers inside stream data are skipped) and just after the header of one that fails to parse; the last occurrence of an object number wins; objects in object streams follow the same rule by container position; the trailer is the last one with `/Root` (XRef stream dictionaries count), else one is synthesised from a `/Type /Catalog` object; `/Prev` and `/XRefStm` are dropped and `/Encrypt`, `/ID`, `/Info` are borrowed from the latest trailer that has them.
- Note: **Object streams that cannot be expanded** (encrypted, or filters beyond Flate until task 10/11) are reported as `ObjectStreamNotExpanded` and their objects are missing, so rebuilding an encrypted file that uses object streams is incomplete until tasks 10/11 add a decrypt/decode hook; revisit then (e.g. pass a decoder into `rebuild`).
- Note: Typed failures: `SyntaxKind::NothingToRecover` (no object found) and `RootNotFound` (objects but no trailer with `/Root` and no catalog); limit errors from `max_xref_entries` apply. The scan has a **work budget of 4 x file size + 1 MiB**: attempts that fail re-read bytes (an unterminated string runs to the end of the file and the scan resumes just after the header), so each failed attempt is charged the bytes it read, plus its window for a failed `endstream` search; once the budget is spent nothing more is parsed. Without it a file of `1 0 obj (` repeated was quadratic (tests with 200,000 repeats finish in about a second now, and did not finish in 150 s before). The normal parse path (no recovery) still searches for `endstream` per stream up to `max_decoded_stream_bytes`, as noted under task 7.
- Note: Corpus (`cargo test -p vellora-cos --test xref_corpus -- --ignored --nocapture`, no qpdf needed for this one): all 275 files either open or fail with a typed error, with a 60 s guard per file: **252 read cleanly, 21 repaired, 2 fail with `NothingToRecover`** (`pdfium-bug_343` and `pdfjs-bug1020226`, 250- and 184-byte files that are mostly garbage and that qpdf cannot recover either). **All 54 files in the `malformed` subset open.** Every in-use entry of a repaired file points at a real object header.
- Note: Not compared against qpdf: object counts of repaired files (qpdf's own reconstruction warns on them, so its numbers are not a clean oracle). Task 13's invariant harness covers write/re-open on repaired files.

### - [x] Task 9: Lazy object store
- **Do:**
  - `ObjectStore`: resolve `(num, gen)` through the newest revision first.
  - A bounded LRU cache of parsed objects.
  - Reference-cycle and depth protection when following refs.
  - Accessors for the trailer, `/Root`, `/Info` and `/Encrypt`.
  - Page-tree traversal that returns page refs lazily, with inherited attributes `/MediaBox`, `/CropBox`, `/Rotate`, `/Resources`, and loop detection.
- **Acceptance:** tests with a cyclic page tree and missing objects (resolve to null, per spec). Opening the 10k-page synthetic file (from task 24's generator or a quick generator in tests) touches O(1) objects until pages are requested.
- **Depends:** 8
- Note: API (`cos::store`, `cos::pages`): `ObjectStore::open(data: &[u8], Limits)` (uses `Xref::open_with_budget`, so it rebuilds a damaged table), `resolve(ObjRef) -> Arc<Object<'static>>`, `deref(&Object)`, `stream_raw(&Stream)`, `trailer()`, `root_ref/root/info/encrypt`, `repaired()` (xref reasons plus per-object ones), `objects_loaded()` (cache-miss counter, for tests) and `pages()`. The store is `Send + Sync` (one mutex); it takes `&[u8]`, so a mapped source plugs in through `ByteSource::slice` once the `MmapSource` question from task 3 is settled.
- Note: Objects are cached as owned `Object<'static>` (new `Object::into_owned`/`Dict::into_owned`); spans are file offsets, except for objects from an object stream (positions in its decoded data). Missing, free and out-of-table objects resolve to `null`; the generation of a reference is ignored (like the recovery scan); parse errors are `Err` for that object only.
- Note: Every in-use offset is checked with `object_header_at` first; the first bad one rebuilds the xref once (`ObjectOffsetInvalid{number}`), later bad ones are `null` (no repeated scans). A rebuilt table has no revision history, so task 12 must do full rewrites for a store whose `repaired()` contains xref reasons. Parser `Recovery` flags are reported as `RepairReason::ObjectRecovered{number, recovery}` (new variant, list capped at 1024).
- Note: New limits: `max_reference_depth` (32, new `LimitKind::ReferenceDepth`; also cuts cycles) and `max_cache_bytes` (64 MiB, applied separately to parsed objects and decoded object streams; not a `LimitKind`). The weight of a cached object is estimated from its node count and string bytes. An object stream bigger than the cache is never cached, so it is re-decoded (and charged to the shared `DecodeBudget`) on each access: bounded, but tune it if task 24 shows it matters.
- Note: `Pages` walks lazily: first page of a 10,000-page file loads exactly 3 objects (catalog, root `/Pages`, page); the root node's own attributes are inherited too. - Note: **Task 10/11 hooks:** object streams decode through `decode_flate_only` and encrypted files are not decrypted. Corpus smoke (`cargo test -p vellora-cos --test store_corpus -- --ignored --nocapture`, no qpdf needed): of 275 files 273 open (the 2 failures are the known `NothingToRecover` ones), no panics or hangs, 262 files yield pages (450 in all). ### - [x] Task 12: Writers: incremental and full (§7.5.6)
- **Do:**
  - Object serialiser (canonical, deterministic output).
  - **Incremental writer:** append new or replaced objects, a new xref section (same style as the file's last section: table or stream), and a trailer with `/Prev`, `/Size`, `/Root` (+ `/Info`, `/ID[0]` preserved, `/ID[1]` updated). **Never touches existing bytes.**
  - **Full writer:** serialises the reachable graph from the trailer (GC), optional object streams and xref stream, fresh `/ID`.
  - Encrypted documents: incremental writes encrypt new objects with the existing key. Full rewrite is unencrypted by default, with explicit re-encryption options (document the choice).
- **Acceptance:**
  - Unit tests.
  - Incremental output = original bytes + appended section (asserted byte-for-byte).
  - Both outputs pass `qpdf --check`.
  - Re-parsing yields the modified object.
- **Depends:** 11
- Note: API (`cos::write`, re-exported at the crate root): `write_object(out, &Object, &Limits)` (canonical, deterministic, `parse(write(x)) == x` proptest), `incremental_update(&store, &Changes) -> Vec<u8>` and `write_full(&store, &FullOptions) -> Vec<u8>`. `Changes` has `set_object(num, NewObject)`, `add_object(&store, NewObject) -> ObjRef`, `free(num)`, `set_info(ObjRef)`; `NewObject` is `Value(Object)` or `Stream { dict, data }` (data already encoded; `/Length` is set by the writer). New helpers: `Object::new(kind)`, `Dict::set/remove`, `Decryptor::encrypt_string/encrypt_stream`, `Error::Write { kind: WriteError }`.
- Note: **`incremental_update` returns only the appended bytes**; the file is `original ++ appended` (the engine copies the original, so the prefix is never rewritten and large files are not duplicated in memory). It refuses with `WriteError::NeedsFullRewrite` when the xref was rebuilt, or when any in-use offset does not point at its object header (`ObjectStore::offsets_are_valid`, because the store checks offsets lazily).
- Note: Incremental details: new section has the same style as the file's newest one (table or xref stream; a hybrid file gets a plain table), `/Prev` is the old section's offset, `/Size` covers everything, `/Root`, `/Info`, `/Encrypt` are copied, `/ID[0]` is kept and `/ID[1]` = first 16 bytes of SHA-256(old `/ID[1]` + appended bytes) (a file with no `/ID` gets one, except an encrypted file). Freed objects are chained through object 0 with generation + 1; older free-list entries that are not freed again are no longer chained. Replacing an object keeps its generation; an object from an object stream is replaced by a plain object (generation 0).
- Note: Full writer: objects reachable from `/Root` and `/Info` are renumbered 1..n (generation 0) in BFS order, unreachable objects and old revisions are dropped, a reference to a missing object becomes `null`, stream data is copied as stored (still under its filters), a `/Crypt` filter is stripped from a stream written unencrypted, a direct `/Info` is dropped, and `/ID` is a fresh hash in both slots. `FullOptions { xref_stream, object_streams (implies xref_stream, 100 objects per stream), encryption }`; header version is raised to 1.5 when xref streams are used. Signatures do not survive a full rewrite.
- Note: **Decision for you (encryption):** the full rewrite is unencrypted by default (`EncryptionPolicy::Remove`); `EncryptionPolicy::Keep` re-encrypts under the same key with the same `/Encrypt` dictionary and `/ID[0]` (same passwords and permissions). Writing a *new* security setup (new passwords or algorithm) is not implemented: it needs random salts (`cos` has no RNG) and a UI decision, so say if you want it as its own task.
- Note: Encryption on write: AES uses a synthetic IV (SHA-256 of key, object id and plain text), so output is deterministic; no randomness or clock is used anywhere in the writers. Incremental updates need an unlocked store (`PasswordRequired` otherwise) and refuse to touch the `/Encrypt` object. All ten encryption fixtures round-trip through incremental, Remove and Keep (R2–R6, with and without object streams) and `qpdf --check` accepts the outputs.
- Note: **Store limit surfaced by the writer:** an object `cos` cannot read is `null` for a full rewrite (or stops it with the store's typed error), so a file like `pdfjs-PDFBOX-3148-2-fuzzed` (its `/Pages` sits in a damaged object stream) is rewritten without pages. The save planner should refuse or warn when a rewrite would drop what the original had; the writer cannot know.
- Note: Tests: `crates/cos/tests/writers.rs` (27 tests: synthetic table, xref-stream, object-stream and hybrid files, refusals, encrypted fixtures) and unit tests next to the code. `cargo test -p vellora-cos --test writers -- --ignored` runs `qpdf --check` on 59 outputs (passes with qpdf 12.4.2); it is `#[ignore]` only because CI has no qpdf until task 13, so **task 13 should drop the ignore**. `--test writers_corpus -- --ignored` (needs the corpus): 275 files, 514 full rewrites reopen unrepaired with the same page count, 232 incremental updates keep the original prefix and the new title, 29 files refused for incremental, 8 full rewrites stop with a typed error (`pdfium-launch_action`, `pdfium-repeat_viewer_ref`: dictionary error; `pdfjs-REDHAT-1531897-0`, `pdfjs-poppler-742-0-fuzzed`: no `/Root`); with `QPDF` set it also checks outputs, counting only files qpdf accepts to begin with.
- Note: Not done (no task asks): linearization (an updated file simply loses it), signature-aware updates (DocMDP), `/Extends` object-stream chains, writing without holding the whole output in memory (the full writer builds a `Vec<u8>`; revisit with task 24's 500 MB document), timing on the 10k-page file.

  - Messages: `Hello{protocol_version}`, `Open{handle_token}`, `Opened{page_count, page_sizes (lazy chunks), repaired}`, `RenderTile{req_id, page, scale, rect, slot}`, `TileReady{req_id, slot}`, `Cancel{req_id}`, `Close`, `Error{req_id?, kind, message}`.

- **Acceptance:** round-trip tests for every message; an oversized frame is rejected before allocation; a version-mismatch test.
- **Depends:** 0
- Note: API: two enums, `Request` (UI to engine: `Hello`, `Open`, `RenderTile`, `Cancel`, `Close`) and `Response` (engine to UI: `Hello`, `Opened`, `TileReady`, `Error`); `read_frame::<_, T>(&mut impl Read) -> Result<Option<T>>` (`None` = clean EOF between frames) and `write_frame(&mut impl Write, &T)`. - Note: Both directions validate (`Validate` trait): a bad message is refused on write and on read (`Error::Invalid`). `RenderTile` limits mirror `vellora-render`'s (scale in (0, 64], sides 1..=4096, area at most 2^24, origin at most 2^24, NaN refused); they are repeated by hand, so keep the two in step. `Opened.page_sizes` is the first chunk only (at most 4096, never more than `page_count`).

There is no compatibility inside a version: any wire change bumps `PROTOCOL_VERSION` (0 then; 1 since task 18).
- Note: **Task 17 decisions left open:** no message carries the later page-size chunks yet (add e.g. `PageSizes { first_page, sizes }` to `Response` when the engine needs it, and bump the version while nothing ships); `repaired` is a `bool`, not the reason list; `handle_token` is an opaque `u64` whose meaning (inherited handle number or lookup key) the engine host defines; `page` is `u32`, so `render` callers convert from `usize`.
- Note: New dependency `postcard` 1.1 (MIT/Apache-2.0, `use-std` only), which adds `cobs` and two `embedded-io` versions to `Cargo.lock` (small, all permissive; `cargo deny check` passes). Tests: 18 unit tests plus three proptests (arbitrary bytes and payloads never panic; anything accepted re-encodes identically).
