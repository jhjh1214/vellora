# Milestone M0 — Walking skeleton

**Goal:** prove the process architecture, the license-clean dependency stack and the `cos` writer invariants end to end, with production OSS infrastructure in place. Plan reference: [`PLAN.md` §O](../PLAN.md). Estimated effort: 8–10 weeks for one developer.

**How to use this file:** follow the *one task per session* protocol in [`CLAUDE.md`](../../CLAUDE.md).
- Take the first unchecked task whose dependencies are checked.
- Implement only its scope and pass its acceptance checks plus the standard checks.
- Tick it, and add `Note:` lines for the next session.
- If a task proves much larger than described, split it here (e.g. 7a, 7b) before implementing.

This file is the hand-off between sessions. Notes go directly under the task they belong to.

**Standard checks** (implied by every task):
`cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace && cargo deny check`

## M0 acceptance criteria (from the plan)

- [ ] CI is green on Windows, Linux and macOS.
- [ ] `cargo deny check` passes; the third-party license list is complete.
- [ ] The engine opens ≥ 95% of corpus v0 without crashing. On the malformed/malicious subset, the **UI process never crashes**.
- [ ] Every incremental write in tests keeps the original byte prefix identical and passes `qpdf --check`.
- [ ] The 10,000-page synthetic document shows its first page in < 1.5 s on the dev machine. Scrolling never blocks the UI thread (UI watchdog log is clean).
- [ ] Re-open-after-commit latency is measured on the 10k-page and 500 MB documents and recorded in an ADR.

## Phase A: foundations

### - [ ] Task 0: Toolchain pin and lockfile
- **Goal:** reproducible builds from the first real commit.
- **Do:**
  - Install Rust via rustup.
  - Set `rust-toolchain.toml` `channel` to the exact current stable version (e.g. `"1.98.0"`).
  - Check that `rust-version` in the workspace `Cargo.toml` is ≤ that version.
  - Run `cargo generate-lockfile` and commit `Cargo.lock` (we ship binaries).
  - In `.github/workflows/ci.yml`, add `--locked` to the cargo build, clippy and test invocations.
  - Install `cargo-deny` locally.
- **Acceptance:** the standard checks pass locally; CI passes with `--locked`.
- **Depends:** —

### - [ ] Task 1: Dev tooling crate (`xtask`) and corpus v0
- **Goal:** a single entry point for dev chores, plus a real-world test corpus.
- **Do:**
  - Add `xtask/` as a workspace member (binary, `publish = false`), with the `cargo xtask` alias in `.cargo/config.toml`.
  - Command `cargo xtask corpus fetch`: reads `tests/corpus/manifest.toml` (`[[doc]] id, url, sha256, license, categories, notes`), downloads into `tests/corpus-data/` (git-ignored), verifies SHA-256, and skips files already verified.
  - Write manifest v0 with **~200 public PDFs** across the categories in [testing-strategy.md](../architecture/testing-strategy.md): pdf.js test corpus, PDFium testing corpus, SafeDocs samples, GovDocs1 sample, Isartor/veraPDF.
  - Include ≥ 30 malformed files. Record the license of every file.
  - Mark the malformed/malicious subset with category `malformed`.
- **Acceptance:** `cargo xtask corpus fetch` downloads and verifies all entries. Re-running is a no-op. A corrupted file is detected and re-fetched.
- **Depends:** 0

### - [ ] Task 2: Spike: `cos` parser foundation → decide ADR-0013
- **Goal:** build-vs-adopt decision for the parser, backed by evidence.
- **Do:**
  - In a throwaway branch or example, evaluate `hayro-syntax` against the criteria in [ADR-0013](../adr/0013-cos-parser-foundation.md): lazy access, byte-span retention, repair on the corpus `malformed` subset, a writer-friendly object model, encryption hooks, and panic-freedom (run a quick fuzz loop).
  - Measure open time and peak memory on the largest corpus file.
- **Acceptance:** ADR-0013 status set to *Accepted* with the chosen option (A, B or C), the measurements, and the API gaps found. Tasks 3–12 adjusted here if the choice changes their shape (e.g. "wrap" instead of "write").
- **Depends:** 1
- **Time-box:** 1 week. If it's inconclusive, choose C (our own) and note why.

## Phase B: `vellora-cos`

All tasks: no panics on input, no unbounded allocation, typed errors (`thiserror`), spec section references in comments. Unit tests use small synthetic byte strings written in the test.

### - [ ] Task 3: Errors, limits and the byte source
- **Do:**
  - `cos::Error` (with byte offset context).
  - `cos::limits::Limits` with documented defaults: max decoded stream bytes, total decode budget per document, decompression ratio cap, max nesting depth, max xref entries, max string/name length, max array/dict entries.
  - A `ByteSource` trait/type with two implementations: memory-mapped file (`memmap2`) and in-memory buffer.
  - Random access by range. Out-of-range access returns `Err`.
- **Acceptance:** unit tests cover every limit default being enforced and out-of-range reads failing cleanly.
- **Depends:** 2

### - [ ] Task 4: Lexer (ISO 32000-2 §7.2)
- **Do:**
  - Tokens with **byte spans**: numbers, literal strings (escapes, balanced parens, line continuation), hex strings, names (`#xx` escapes), delimiters, keywords, comments, `stream` keyword handling (EOL rules).
  - Whitespace and comments are tracked but skippable.
- **Acceptance:** tests for every token type plus malformed variants (unterminated strings, odd hex digits, huge numbers). A proptest shows the lexer never panics on arbitrary bytes.
- **Depends:** 3

### - [ ] Task 5: Object parser
- **Do:**
  - Direct objects (null, bool, int, real, string, name, array, dict, ref `n g R`) and indirect objects `n g obj … endobj`.
  - Streams: `/Length` direct or indirect. If the length is wrong or missing, recover by searching for `endstream` within limits, and flag the recovery.
  - Every parsed object keeps its source span.
- **Acceptance:** tests including a wrong `/Length`, missing `endobj`, deep nesting hitting the limit, and dictionaries with duplicate keys (last one wins, documented).
- **Depends:** 4

### - [ ] Task 6: Classic xref and trailer chain
- **Do:**
  - `startxref` lookup (search the last N KB).
  - Xref tables (subsections, free list, 20-byte entries with tolerant EOL handling), trailer dict, and the `/Prev` chain with loop detection.
  - Build a revision list (each revision = its xref section plus byte range).
- **Acceptance:** tests on synthetic single-revision and multi-revision files. A `/Prev` loop is detected. Every corpus file that has a valid classic xref yields the same object count as `qpdf --show-xref` (sampled).
- **Depends:** 5

### - [ ] Task 7: Xref streams, object streams, hybrid files (§7.5.7–7.5.8)
- **Do:**
  - `/Type /XRef` streams (`/W`, `/Index`, `/Prev`), including decoding through Flate + predictor.
  - Object streams (`/Type /ObjStm`, `/N`, `/First`) with lazy extraction.
  - Hybrid files (`/XRefStm`).
  - Before task 10 lands, implement only the minimal Flate path this needs, and reuse it there.
- **Acceptance:** synthetic tests plus agreement with `qpdf --show-xref` on sampled corpus files with xref streams.
- **Depends:** 6

### - [ ] Task 8: Recovery scan
- **Do:**
  - When `startxref` or the xref is missing or broken, rebuild by scanning for `n g obj` headers and trailer dicts (or `/Root` candidates).
  - Set a `repaired` flag carrying the reasons.
  - Never trust offsets without validation.
- **Acceptance:** every corpus `malformed` file either opens (with `repaired = true`) or fails with a typed error. **No panics, no hangs** (a test timeout guards it).
- **Depends:** 7

### - [ ] Task 9: Lazy object store
- **Do:**
  - `ObjectStore`: resolve `(num, gen)` through the newest revision first.
  - A bounded LRU cache of parsed objects.
  - Reference-cycle and depth protection when following refs.
  - Accessors for the trailer, `/Root`, `/Info` and `/Encrypt`.
  - Page-tree traversal that returns page refs lazily, with inherited attributes `/MediaBox`, `/CropBox`, `/Rotate`, `/Resources`, and loop detection.
- **Acceptance:** tests with a cyclic page tree and missing objects (resolve to null, per spec). Opening the 10k-page synthetic file (from task 24's generator or a quick generator in tests) touches O(1) objects until pages are requested.
- **Depends:** 8

### - [ ] Task 10: Stream filters (§7.4)
- **Do:**
  - Decode FlateDecode (+ PNG/TIFF predictors), LZWDecode (+ EarlyChange), ASCIIHexDecode, ASCII85Decode and RunLengthDecode, plus filter chains and `/DecodeParms`.
  - DCT, JPX, CCITT and JBIG2 pass through undecoded (PDFium handles images).
  - Every decoder enforces `Limits` (output size and ratio).
- **Acceptance:** known-answer tests per filter. A decompression-bomb test (tiny input that would expand to > limit) fails with `Error::LimitExceeded`.
- **Depends:** 9

### - [ ] Task 11: Decryption: Standard Security Handler R2–R6 (§7.6)
- **Do:**
  - RC4 40/128-bit, AES-128 (V4 crypt filters), AES-256 (R5/R6). Empty user password by default; a password API for the UI.
  - Strings and streams decrypted on access.
  - `/Identity` crypt filter; metadata left unencrypted when `/EncryptMetadata false`.
  - Use RustCrypto crates (license check).
- **Acceptance:** test vectors per revision (generate fixtures with qpdf in the test setup, or commit small generated fixtures with the generator script). Encrypted corpus files open with the empty password; a wrong password gives a typed error.
- **Depends:** 10

### - [ ] Task 12: Writers: incremental and full (§7.5.6)
- **Do:**
  - Object serialiser (canonical, deterministic output).
  - **Incremental writer:** append new or replaced objects, a new xref section (same style as the file's last section: table or stream), and a trailer with `/Prev`, `/Size`, `/Root` (+ `/Info`, `/ID[0]` preserved, `/ID[1]` updated). **Never touches existing bytes.**
  - **Full writer:** serialises the reachable graph from the trailer (GC), optional object streams and xref stream, fresh `/ID`.
  - Encrypted documents: incremental writes encrypt new objects with the existing key. Full rewrite is unencrypted by default, with explicit re-encryption options (document the choice).
- **Acceptance:**
  - Unit tests.
  - Incremental output = original bytes + appended section (asserted byte-for-byte).
  - Both outputs pass `qpdf --check`.
  - Re-parsing yields the modified object.
- **Depends:** 11

### - [ ] Task 13: Invariant harness, property tests, fuzzing, qpdf in CI
- **Do:**
  - `tests/invariants/`: for every corpus file that opens, (a) full-write → qpdf check → re-parse with the same page count; (b) incremental-write one modified `/Info` → prefix byte-identical → qpdf check.
  - `proptest`: parse(write(obj)) == obj for generated objects.
  - `fuzz/` (cargo-fuzz, a separate non-workspace crate) with targets `lexer`, `object_parser`, `xref_open` (whole-document open), `write_roundtrip`.
  - CI: install qpdf on all OSes; run the invariant harness on a small committed-manifest subset (≤ 20 files); fuzz smoke 60 s per target on Linux (nightly toolchain only in that job).
  - `nightly.yml`: full corpus + 30 min per fuzz target.
- **Acceptance:** CI is green with the new jobs. Any fuzz crash found during the task is fixed, with a regression test.
- **Depends:** 12, 1

## Phase C: rendering and the engine

### - [ ] Task 14: PDFium acquisition and bindings (`vellora-render`)
- **Do:**
  - `third_party/pdfium.lock`: pinned `bblanchon/pdfium-binaries` release tag + per-platform asset name + SHA-256 (V8- and XFA-free builds).
  - `cargo xtask pdfium fetch` downloads and verifies into `third_party/pdfium/<platform>/`.
  - Bindings for the narrow API surface (~20 functions: init/destroy library, load doc with custom `FPDF_FILEACCESS`, page count, load/close page, page size, bitmap create (external buffer), render page bitmap with matrix/clip, last error).
  - Decide between thin committed `bindgen` output and the `pdfium-render` crate (MIT/Apache). Prefer thin bindings for control and a minimal surface, and record the choice in a short ADR.
  - Link dynamically; the engine ships the shared library alongside itself.
- **Acceptance:** `cargo test -p vellora-render` loads PDFium and reports the page count of a fixture on all three OSes in CI.
- **Depends:** 0

### - [ ] Task 15: Safe render API
- **Do:**
  - `Renderer` owning a dedicated PDFium thread (all FFI calls are marshalled to it).
  - `open(revision bytes provider) -> DocHandle`, `page_count`, `page_size(i)`, `render_tile(page, scale, rect, &mut [u8] stride) -> Result`.
  - Every `unsafe` block carries a `// SAFETY:` comment. Panics never cross the FFI boundary.
- **Acceptance:** a golden-render test renders 3 fixture pages and compares against committed PNGs with a small perceptual tolerance. A test drives concurrent requests from many threads (serialised internally).
- **Depends:** 14

### - [ ] Task 16: IPC protocol v0 (`vellora-ipc`)
- **Do:**
  - Messages: `Hello{protocol_version}`, `Open{handle_token}`, `Opened{page_count, page_sizes (lazy chunks), repaired}`, `RenderTile{req_id, page, scale, rect, slot}`, `TileReady{req_id, slot}`, `Cancel{req_id}`, `Close`, `Error{req_id?, kind, message}`.
  - Length-prefixed `postcard` framing with a size cap; sync reader and writer over `Read`/`Write`.
- **Acceptance:** round-trip tests for every message; an oversized frame is rejected before allocation; a version-mismatch test.
- **Depends:** 0

### - [ ] Task 17: Engine host v0
- **Do:**
  - `vellora-engine`: parse launch arguments (IPC pipe handles, file handle, shared-memory name/handle, limits).
  - Handshake. Open the document with `cos` (store) and PDFium (render), serving PDFium the bytes from the `ByteSource`.
  - **Cross-check** page count and page refs; set `repaired` on mismatch.
  - Serve `RenderTile` into shared-memory slots (`shared_memory`/`memmap2`-backed; OS-specific code isolated in one module).
- **Acceptance:** an integration test spawns the engine, opens a fixture, renders a tile and checks its pixels against the golden image.
- **Depends:** 13, 15, 16

### - [ ] Task 18: Scheduler with priorities and cancellation
- **Do:**
  - Priority queue (visible > prefetch > thumbnail).
  - `Cancel` removes queued work. In-flight work completes, but its result is discarded.
  - Per-job soft deadline (logged) and hard deadline (handed to the watchdog).
- **Acceptance:** tests show cancelled requests never produce `TileReady`, and that priority ordering holds under load.
- **Depends:** 17

### - [ ] Task 19: Watchdog and OS resource limits
- **Do:**
  - The parent side (in `engine-client`, but the limit setup code lives with the spawn code) applies a Windows Job object (memory limit, kill-on-close, no child processes) or `setrlimit` (RLIMIT_AS/DATA, CPU) on Linux and macOS.
  - The engine aborts itself if a PDFium call exceeds its hard deadline; the client treats EOF as a crash.
  - Document what is **not** sandboxed yet in the security model's tracker.
- **Acceptance:** tests where (a) a bomb fixture hits the memory limit, the engine dies, and the client reports a typed crash; (b) a simulated hang is killed within its deadline.
- **Depends:** 18

### - [ ] Task 20: Engine client and cxx bridge (`vellora-engine-client`)
- **Do:**
  - Spawn the engine with handles and limits.
  - Typed async-ish API (callbacks or a polled event queue; choose the one that maps cleanly to the Qt event loop and document it).
  - Restart on crash, re-opening the document.
  - Set `crate-type = ["staticlib", "rlib"]`.
  - `cxx` bridge exposing: `open(path)`, `page_count`, `page_size`, `request_tile`, `cancel`, `poll_events`, `close`. No Qt types.
- **Acceptance:** a Rust integration test drives the full open → tile → crash → restart → tile cycle. The C++ header is generated in the build.
- **Depends:** 19

### - [ ] Task 21: Client tile cache
- **Do:**
  - Shared-memory slot allocator plus an LRU tile cache with a byte budget (default 256 MB).
  - Cache key `(page, scale bucket, tile x/y)`; invalidation by page.
- **Acceptance:** unit tests for eviction order and budget enforcement.
- **Depends:** 20

## Phase D: user-facing surfaces

### - [ ] Task 22: Qt shell skeleton (`app/`)
- **Do:**
  - CMake (≥ 3.28) + Qt 6.8 LTS Widgets + Corrosion, building `vellora-engine-client` as a staticlib and `vellora-engine` as a sibling executable.
  - Main window with a native menu bar.
  - File → Open (dialog). Continuous vertical scroll with correctly sized placeholders. Async tiles drawn in a `QRhiWidget` canvas.
  - Zoom (Ctrl+wheel, Ctrl+±, fit width). Status bar showing page N / M and zoom.
  - **Command registry** (id, title, shortcut, handler) with 3 commands (open, zoom in, zoom out) and a command palette stub (Ctrl+Shift+P) listing registry entries.
  - An engine crash shows a non-modal "page failed to render — retrying" state.
  - In debug builds, a UI-thread watchdog logs any event-loop stall > 16 ms.
  - CI: add a C++ job (Qt via `jurplel/install-qt-action`) building `app/` on all three OSes, plus `clang-format --dry-run -Werror`.
- **Acceptance:** CI builds the app on all OSes. Manually: open a 10k-page synthetic file and scroll with no stalls in the watchdog log; kill the engine process and the app recovers. Record a short note of the manual verification in this task.
- **Depends:** 21
