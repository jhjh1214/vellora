# Milestone M3 — Annotations & comments (v0.3)

**Goal:** professional review markup stored as **standard PDF annotations** (ISO 32000-2 §12.5), so it round-trips with Acrobat and other viewers: highlights, ink, shapes, text boxes, notes, stamps, threaded replies and review status. This milestone also builds the **font subsystem** that M4's text editing and every generated appearance reuse. Plan reference: [`PLAN.md` §C, §K](../PLAN.md) (phase 3), [data-model.md § Review state](../architecture/data-model.md). Estimated effort: 8–10 weeks.

**How to use this file:** the *one task per session* protocol in [`CLAUDE.md`](../../CLAUDE.md) and the [milestone rules](README.md#rules-for-every-milestone).

## M3 acceptance criteria

- [ ] Every supported annotation type can be created, edited, moved, resized and deleted, and is saved incrementally with our own appearance stream.
- [ ] Round-trip: annotations created by Vellora render the same in PDFium and pdf.js (automated) and in Adobe Acrobat (manual checklist with screenshots). Replies, status, author and dates survive a save in Acrobat and back.
- [ ] Annotations made by other tools (corpus) are preserved byte-identically unless edited. Unknown keys survive edits.
- [ ] Untouched pages stay pixel-identical after annotation saves (invariant harness).
- [ ] Comments panel: filter, threads, status and navigation work on a document with 5,000 annotations within the frame-time budget.
- [ ] XFDF export and import round-trips our annotations.
- [ ] Tagged pre-release `v0.3.0`, only if the maintainer asks.

### - [ ] Task 1: Annotation read model
- **Do:**
  - In `doc`: typed views for annotations:
    - common entries: `/Subtype`, `/Rect`, `/NM`, `/T`, `/M`, `/CreationDate`, `/F` flags, `/C`, `/CA`, `/Border`/`/BS`, `/Contents`, `/RC` read as plain text, `/IRT` + `/RT`, `/State` + `/StateModel`, `/Popup`
    - per-type data: `QuadPoints`, `InkList`, `Vertices`, `L`, `LE`, `DA`, `Q`, `CL`, `IT`, `Name`
  - PDF date parsing/formatting (§7.9.4), tolerant of real-world variants.
  - Protocol `GetAnnotations(page)` returns a plain-data list plus a document-wide paged listing for the comments panel.
- **Acceptance:** corpus test reading every annotation with no panics. Unit tests for dates and every type's fields.
- **Depends:** 0

### - [ ] Task 2: Font subsystem (`fonts` crate)
- **Goal:** one place that turns a string + font choice into embeddable PDF font objects and positioned glyphs.
- **Do:**
  - New crate `crates/fonts` (`vellora-fonts`):
    - font discovery (system fonts via `fontdb` or similar, plus the bundled fallback per decision #3)
    - shaping with `harfrust`
    - metrics with `skrifa`/`read-fonts`
    - subsetting (`subsetter` or equivalent; check licenses)
    - embedding as `Type0`/`CIDFontType2` (TrueType outlines) or `CIDFontType0` (CFF), with `/W` widths and a correct **`ToUnicode` CMap**
  - Fast path: the standard 14 Helvetica/Times/Courier with WinAnsiEncoding for Latin-1 text (no embedding), with metrics tables from a permissively licensed source (record it in NOTICE).
  - Respect the OS/2 `fsType` embedding permissions: refuse restricted fonts and fall back with a reason.
  - ADR "Font strategy for generated content".
- **Acceptance:**
  - Unit tests for shaping (Latin, Arabic, Devanagari, CJK) and subsetting.
  - Text written with each embedding path extracts back to the same Unicode through PDFium's text API and renders correctly.
  - `cargo deny` passes.
- **Depends:** 0

### - [ ] Task 3: Appearance stream generator
- **Do:**
  - Deterministic `/AP /N` generation for:
    - Square, Circle, Line with line endings (`/LE`: Square, Circle, Diamond, OpenArrow, ClosedArrow, Butt, ROpenArrow, RClosedArrow, Slash)
    - Polygon, PolyLine, Ink
    - Highlight (multiply blend through `/ExtGState` `/BM /Multiply`), Underline, StrikeOut, Squiggly (from `QuadPoints`)
    - FreeText (wrapping, alignment `/Q`, padding, border, `/DA` font through task 2) and FreeText callout (`/CL`, `/IT /FreeTextCallout`)
    - Text (sticky note icons: Comment, Key, Note, Help, NewParagraph, Paragraph, Insert), Caret
    - Stamp (standard names: Approved, Draft, Confidential, Final, NotApproved, ForComment, … rendered as bordered text; and custom image stamps)
  - Opacity via `/CA` and an ExtGState. Rotation-aware (`/Rotate` pages).
- **Acceptance:** golden-render tests for every type and option (PDFium) and visual comparison against pdf.js rendering of the same file (headless pdf.js as a dev-only test tool) within tolerance.
- **Depends:** 1, 2

### - [ ] Task 4: Annotation operations
- **Do:**
  - `ops`: `AddAnnotation{page, spec}`, `ModifyAnnotation{id, changes}`, `DeleteAnnotation`, `MoveAnnotation`, `ResizeAnnotation`, `AddReply{parent, text}`, `SetReviewState{id, state, author}` (a reply with `/State`/`/StateModel` per §12.5.6.3), `SetAnnotationFlags` (hidden, print, locked, read-only).
  - Unique `/NM` ids; `/T` from the author identity (task 9); `/M` and `/CreationDate`; the `/P` back-reference; the page `/Annots` array updated.
  - Each change regenerates the AP (task 3). Unknown keys are preserved on modify.
  - Deleting a parent deletes its replies (with confirmation in the UI).
- **Acceptance:** unit tests per op. Invariant: saving after one annotation change leaves every other annotation object byte-identical in the output.
- **Depends:** 3

### - [ ] Task 5: Engine and canvas plumbing for live annotation editing
- **Do:**
  - The UI draws in-progress shapes (ink strokes, rectangles, text box frames) itself on an overlay layer for zero-latency feedback, then sends the op. The engine commits and re-renders the page (ADR-0016), and the overlay hands over to the real render without flicker.
  - Hit-testing of existing annotations through rects from `GetAnnotations`.
- **Acceptance:** frame-time test while drawing ink at 120 Hz input on the 10,000-page document. No flicker in the commit hand-over (render-sequence test).
- **Depends:** 4

## Phase B: user interface

### - [ ] Task 6: Annotate mode and tools
- **Do:**
  - An Annotate mode with a single contextual toolbar:
    - select (move/resize handles; multi-select; arrow-key nudging)
    - highlight/underline/strikeout/squiggly **from text selection** (M1 text model → `QuadPoints`)
    - freehand ink (smoothing; pen pressure ignored for now)
    - rectangle, ellipse, line, arrow, polygon, polyline, cloud border (optional)
    - text box, callout, sticky note, stamp picker (standard + custom image), caret/insert text
  - Properties strip: colour, opacity, line width, line style, font and size for text.
  - Tool shortcuts (e.g. H, U, S, P, R, O, L, A, T, N) shown in the palette. Esc returns to select. Locked annotations can't be moved.
- **Acceptance:** Qt tests drive each tool to the expected op. Manual checklist with screenshots in the PR.
- **Depends:** 5

### - [ ] Task 7: Comments panel
- **Do:**
  - A right-side panel listing all annotations in a virtualised list: page, author, date, type, status and text excerpt.
  - Filter by author, type, status and page range; search the text; sort by page, date or author.
  - **Threaded view** of replies with an inline reply box. Status menu: Accepted, Rejected, Cancelled, Completed, None. Show/hide completed. Click to navigate and select on the canvas; selection on the canvas selects the item.
  - Sticky-note popups are shown and edited in the panel (no floating popup windows) and highlighted on the canvas.
- **Acceptance:** tests on a generated document with 5,000 annotations and 1,000 replies: filters are correct, and frame time is within budget.
- **Depends:** 6

### - [ ] Task 8: Accessibility of annotations
- **Do:** annotations become accessible children of their page (type, author, contents). There's a keyboard way to create a note at the caret (M1 task 17's caret browsing) and to move between annotations (Ctrl+Alt+Down/Up). The checklist is extended.
- **Acceptance:** accessibility tests read annotation contents. The checklist is executed.
- **Depends:** 7

## Phase C: interchange and quality

### - [ ] Task 10: XFDF export/import and comment summary
- **Do:**
  - Export annotations to **XFDF** (ISO 19444-1) and import them, matching by `/NM` (updates) or creating new (with an option to replace or merge).
  - Export a comment summary as Markdown, CSV or JSON (page, author, date, type, status, text, replies).
  - Use an XML crate that passes the dependency policy, with entity expansion disabled (XXE-safe).
- **Acceptance:** our annotations round-trip through XFDF unchanged. XFDF exported from Acrobat test files imports (fixtures with licenses). An XXE test file is rejected.
- **Depends:** 4

### - [ ] Task 11: Flatten annotations
- **Do:**
  - `FlattenAnnotations{selection | all, include_hidden: false}` turns appearances into page content (wrapped as Form XObjects in an appended content stream) and removes the annotations.
  - `SaveImpact` lists it as destructive (comments become non-editable).
- **Acceptance:** flattened pages render pixel-identically to the annotated pages (print flag respected). Annotations are gone from the output.
- **Depends:** 4
