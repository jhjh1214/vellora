# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Printing: File → Print (Ctrl+P) and Print Preview. Choose all pages, the current page or a range that accepts page labels ("ii-v, 7"), odd or even pages, fit to page, actual size or shrink oversized pages, turning and centring, and grayscale, then the printer in the system dialog. The engine draws each page in bands at the printer's resolution, annotations the way a printer shows them, with a progress window and Cancel. A document that forbids printing is not printed and says why; one that allows low resolution only is printed at 150 dpi. There is no "print to PDF" here (protocol v8; `docs/user/printing.md`).
- Document Info (View → Document Info, Ctrl+I): properties (version, pages and their sizes, title, author, dates, tagged, linearized), security (encryption and what the author allows, the risky features found, each with a plain explanation, the addresses links point to and the names of embedded files), revisions with their byte ranges, and repairs. File → Export Report as JSON writes the same report as `vellora inspect --json`; the engine makes it and the shell shows it as plain text (protocol v9; `docs/user/inspector.md`).
- Accessibility: the canvas is a document of pages for screen readers (text of each page in reading order, the links as focusable, pressable items, the page announced when it changes); F7 turns on caret browsing (arrows, Ctrl+arrows, Home/End, Shift to select, across pages); F8 and Shift+F8 step through links with a visible ring; every command is in the palette (Ctrl+Shift+P) with its shortcut. `docs/dev/accessibility-checklist.md` lists the manual NVDA and Orca steps, which have not been run yet.
- Command line: `vellora security <file> [--json]` (exit 0 nothing risky, 3 risky features, 1 error or an incomplete scan), `vellora render <file> --pages 1-5,8 --dpi 150 -o <folder|file.png>` and `vellora text <file> [--pages 1-5,8,10-]`, which use the sandboxed engine. `inspect` and `--json` report the document information, page sizes, revision byte ranges, link addresses and embedded file names (`docs/user/cli.md`).
- Quality gates: a rendering regression suite (43 pages of 40 corpus documents against goldens kept as a release asset, tolerance per operating system) runs in CI on Windows, Linux and macOS; the nightly job also runs the engine corpus gate, the `cos` and `inspect` corpus tests and a benchmark gate that measures the previous revision beside the current one and fails on a regression of more than 10% (Linux and Windows; macOS is reported). Numbers are in ADR-0016.
- Internationalisation: all user-visible strings go through `tr()`; `VELLORA_LOCALE=pseudo` (accented, longer) and `pseudo-rtl` (right-to-left) check layouts; a test finds untranslated literals in `app/src`.
- Packaging: nightly builds publish a rolling `nightly` pre-release with an unsigned per-user Windows MSI (opt-in `.pdf` association), a Flatpak on the KDE 6.8 runtime, an unsigned macOS `.dmg` for testers, `SHA256SUMS` and a CycloneDX SBOM. Each artifact is smoke-tested in CI.
- User manual: an mdBook in `docs/user/` (install, first steps, viewing, search, printing, shortcuts generated from the command registry, CLI, privacy, security) built in CI.
- Search: Edit → Find (Ctrl+F) opens a find bar that searches the text of the whole document while you keep reading. Options: match case, whole words, regular expression. Results are highlighted on the pages (the current one in orange), listed in the sidebar (View → Search Results, Ctrl+Shift+F) and stepped through with F3 and Shift+F3; the view follows. A phrase can run over a line break. The search runs in the engine, page by page (the first hit of a 10,000-page document in under a second, a thousand pages in well under three seconds), is cancelled by a newer search or Escape, and stops after 10,000 results. Details and limits in `docs/user/search.md` (protocol v7).
- Text: select text with the mouse (drag, double-click for a word, triple-click for a line, Shift+click to extend, drag past the window edge to go on across pages), Select All (Ctrl+A, with a question for documents over 1,000 pages) and Select All on Page (Ctrl+Shift+A), and copy it with Ctrl+C as plain text. The pointer is a text cursor over text. The known limits (right-to-left and vertical text, rotated pages) are in `docs/user/text-selection.md`.
- Links: links in a document are clickable. Jumps inside the document work like the outline (Alt+Left comes back); a web or mail address is shown in full and opened only after you confirm it (you can stop being asked about a site for the current document); addresses of other kinds are refused; actions a PDF can ask for, such as running a program or a script, are described and never run. The pointer and the tool tip show where a link goes.
- Outline and navigation: the sidebar has an Outline tab (View → Outline, Ctrl+Shift+O) with the document's bookmarks, read a level at a time as you expand them, which follows the page you are on and jumps when you click. Page labels ("iv", "A-3") show in the thumbnails and the status bar; Go to Page (Ctrl+G, or click the page text) takes a label or a number; Alt+Left and Alt+Right go back and forward through your jumps.
- Page thumbnails: a sidebar on the left (View → Page Thumbnails, F4) with a thumbnail and the page label for every page, drawn lazily as you scroll; the page you are reading is highlighted, a click or the arrow, Page Up/Down, Home and End keys jump to a page, and the size is set with the slider or Ctrl+wheel. Thumbnails have a cache of their own (64 MB) and are rendered after every visible tile, so a fling through a 10,000-page document does not slow the page you are reading.
- View modes: single page or continuous scrolling, one or two pages a row (with an optional cover page), the view can be turned in quarter turns (never written to the file), fit width, fit page, zoom presets from 25% to 6400%, zoom to a dragged rectangle (hold Z) and to the cursor (Ctrl+wheel). Old tiles stay on screen, scaled, until the sharp ones arrive. The arrangement is remembered for each document and for new ones.
- Crash reports, all local: if the application crashes, a monitor process writes a minidump (the stacks of the threads, not the heap) into the crash folder, and the next start offers to open the folder or a prefilled GitHub issue (nothing is attached or uploaded). If the sandboxed engine crashes or panics, the app records what happened with the engine's last 200 log lines. See ADR-0019.
- Logs: the application writes rotating log files (at most 10 MiB) to the platform's log folder, including the sandboxed engine's log lines, which the UI process now reads from the engine's standard error. Help → Open Log Folder shows the folder; `VELLORA_LOG_DIR` and `VELLORA_LOG` change where and how much.
- Help → About Vellora: version, commit and build date, the MPL-2.0 license, the Qt LGPL notice with how to replace Qt, and a viewer for the licenses of every bundled component (Rust crates, PDFium and the libraries inside it, Qt). `cargo test` fails when `THIRD_PARTY_LICENSES` lacks a crate that is linked.
- Tabs: every document opens in its own tab with its own engine process (Ctrl+Tab, Ctrl+Shift+Tab, Ctrl+W, Ctrl+Shift+T to reopen). Files can be given on the command line, dropped on the window or chosen from File → Open Recent (15 files, unreadable ones greyed out); a second launch hands its files to the running window. The window size and, for each file, the page and zoom it was left at are remembered.
- Encrypted documents: the engine opens them with a password (user or owner, any revision of the Standard Security Handler). A document that needs one is refused with a typed `PasswordRequired`, a wrong password with `WrongPassword`; the shell asks in a modal prompt with three attempts and never logs or stores the password. Revision 6 passwords are SASLprep-normalised, older ones are also tried as Latin-1 (protocol v3).
- Repository foundation: governance documents, architecture documentation and ADRs, Rust workspace skeleton, CI.
- `cargo xtask pdfium fetch`: downloads the PDFium build pinned in `third_party/pdfium.lock`, verifies its SHA-256 and extracts it.
- `vellora-render`: thin bindings to PDFium, loaded at run time (ADR-0014).
- `vellora inspect <file> [--json] [--password <pw>]`: version, pages, objects, revisions, encryption, repairs and risky features (JavaScript, launch/URI/submit/remote actions, embedded files, forms, XFA, layers, signature fields). Output formats in `docs/user/cli.md`.
- `cargo xtask bench`: synthetic 10,000-page and ~500 MB documents and a harness for open → first page, peak memory and re-open-after-commit latency (ADR-0016).
- Corpus gate: `crates/engine/tests/corpus.rs` opens every corpus v0 document in the engine and renders page 1 (97.0% of the non-password files open, no engine crash or hang).
- `THIRD_PARTY_LICENSES` (cargo-about for Rust crates, plus PDFium and Qt notices); milestone M1 (viewer) task plan.

### Fixed
- The Windows sandbox could fail to start an engine when several `vellora` processes started engines at the same moment; it now retries.
- An incremental update could give a new object a number that the trailer already named without defining (for example `/Encrypt 8 0 R` with `/Size 8`), changing what that reference meant. Found by the nightly fuzzer.
